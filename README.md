# gm-screen

Ширма мастера для D&D 5e (2014) — самодостаточное одностраничное веб-приложение.
Экран целиком живёт в браузере (localStorage), сервер ему не нужен.

- Фронт: `web/index.html` — самодостаточный HTML (ваниль JS, без сборки), 16 приключений,
  статблоки, кубы, трекер инициативы, читалка доков, бестиарий, **вкладка «Партия»**.
- Бэк (опционально): `main.go` + `parse.go` — `net/http` со статикой и одной ручкой
  `POST /api/parse-character`. Ручка платная (дёргает Claude твоим ключом), поэтому
  **на прод не деплоится** — только для локального удобства (см. ниже).

## Импорт персонажей — локально, без ключей

Основной путь: разобрать чарник **локальным скиллом** и вставить готовый JSON в экран —
ни API-ключей, ни платных веб-ручек, работает даже на задеплоенной статике.

1. Скилл `parsing-character-sheets` (в `.claude/skills/`) под твоей подпиской приводит текст
   чарника (или скрин/PDF) к `gm-character/v1` и отдаёт JSON.
2. Вкладка **«Партия»** → вставить JSON в поле → «Импортировать». Карточка добавляется
   **аддитивно** — уже загруженные персонажи не затираются; битый ввод партию не трогает.
   Поле принимает и один объект, и массив `[…]` (несколько разом).

Локальный «в один клик» (по желанию): если запустить `go-screen` со своим `ANTHROPIC_API_KEY`,
то же поле принимает **сырой текст** и парсит его через `POST /api/parse-character`. Этот путь
только для локального запуска — ключ на публичный прод не кладём.

Контракт формата — в **[FORMAT.md](FORMAT.md)** и **[web/character.schema.json](web/character.schema.json)**:
и скилл, и сервер отдают ровно эту форму, велосипед не переизобретается.

> ⚠️ **Репозиторий публичный.** Никаких ключей в git. Все секреты — в `secrets/`
> (папка в `.gitignore`), на проде — через EnvironmentFile / секрет-менеджер хоста.

## Быстрый старт

```bash
# 1) положи ключ (файл secrets/env НЕ коммитится)
cp secrets/env.example secrets/env
$EDITOR secrets/env          # впиши ANTHROPIC_API_KEY=sk-ant-...

# 2) собери и запусти
go build -o gm-screen .
set -a; . ./secrets/env; set +a
./gm-screen
# → http://localhost:8777  (экран мастера; вкладка «Партия» — импорт игроков)
```

Без ключа сервер всё равно поднимется и раздаст экран — не работает только импорт
персонажей (ручка вернёт `503 ANTHROPIC_API_KEY is not set`). Всё остальное на экране
живёт целиком в браузере и сервер ему не нужен.

## Переменные окружения

| Переменная          | По умолчанию        | Зачем |
|---------------------|---------------------|-------|
| `ANTHROPIC_API_KEY` | —                   | Ключ для импорта персонажей. Только для `/api/parse-character`. |
| `PORT`              | `8777`              | Порт HTTP. |
| `PARSE_MODEL`       | `claude-opus-4-8`   | Модель-парсер. Строкой, чтобы пережить смену версий SDK. |
| `GM_WEB_DIR`        | `./web`             | Откуда раздавать статику. |

## API

### `POST /api/parse-character`
```jsonc
// запрос
{ "text": "любой текст чарника: экспорт D&D Beyond, OCR со скрина, описание словами…" }
// ответ 200 — объект gm-character/v1 (см. FORMAT.md)
{ "schema":"gm-character/v1", "name":"…", "level":3, "ac":15, "hp":{…}, "abilities":{…}, … }
```
Коды ошибок: `400` пустой/битый body, `422` модель не вернула валидный JSON,
`502` вызов модели упал, `503` не задан ключ.

## Деплой

### Прод (`smoreg.dev/gm-screen/`) — статика + логин/пароль, без ключа

На прод едет **только `web/`** — статика без сервера и без `ANTHROPIC_API_KEY`. Импорт
персонажей работает через локальный скилл (вставляешь готовый JSON), так что платной ручки
на проде нет и слить кредиты нельзя. Экран закрыт простейшей **owner-gated** авторизацией
(nginx Basic Auth): логин/пароль, аккаунты заводит только владелец командой `htpasswd`.

Конфиг и пошаговые команды — в **`deploy/nginx-gm-screen.conf`** (в шапке файла). Кратко:
```bash
rsync -a web/ root@smoreg.dev:/var/www/gm-screen/
scp deploy/nginx-gm-screen.conf root@smoreg.dev:/etc/nginx/snippets/gm-screen.conf
# завести юзеров (это и есть «рега с моего разрешения»):
ssh root@smoreg.dev 'htpasswd -B -c /etc/gm-screen/.htpasswd kirill'   # первый
ssh root@smoreg.dev 'nginx -t && systemctl reload nginx'
```
Редеплой = повторить `rsync web/`. Пароли живут только на хосте (репа публичная — не коммитим).

### Локально — go-сервер с ключом (для «в один клик» из сырого текста)

Ключ живёт **вне** git и на прод не едет.

**systemd** (см. `deploy/gm-screen.service`) — ключ в EnvironmentFile `/etc/gm-screen/env`
(`chmod 600`). Для локальной машины/доверенного хоста, не для публичного прода.

**Docker** (см. `Dockerfile`) — multi-stage, статик-бинарь на `gcr.io/distroless/static`.
Ключ пробрасывается на рантайме, в образ не пекётся:
```bash
docker build -t gm-screen .
docker run -p 8777:8777 --env-file ./secrets/env gm-screen
```

## Раскладка

```
go-screen/
  main.go                 HTTP-сервер, роутинг, middleware, конфиг из env
  parse.go                вызов Claude, извлечение и нормализация JSON
  FORMAT.md               человекочитаемый контракт gm-character/v1
  web/
    index.html            вся ширма мастера (раздаётся как есть)
    character.schema.json JSON Schema формата персонажа
    ФАЗА-1_канон-и-сюжет.md, ФАЗА-2_боевой-чистовик.md   модуль про коров
    docs_txt/*.txt        тексты всех 16 приключений для читалки
  secrets/
    env.example           шаблон (коммитится)
    env                   реальный ключ (в .gitignore, НЕ коммитится)
  deploy/
    gm-screen.service     unit для systemd (локальный запуск с ключом)
    nginx-gm-screen.conf  nginx-сниппет для прод-статики + Basic Auth (owner-gated)
  .claude/skills/
    parsing-character-sheets/  локальный скилл: текст чарника → gm-character/v1 (без ключа)
  Dockerfile
```
